# ACTION OS

2026年10月20日版。成人の救命対応を中心に、1事案を1ページで操作する端末保存型Webアプリです。

## 公開サイトとGit管理

- 公開サイト：[ACTION OS](https://taka565.github.io/action-os/)
- ソースコード：[taka565/action-os](https://github.com/taka565/action-os)
- 公開状況：[GitHub Actions](https://github.com/taka565/action-os/actions/workflows/pages.yml)

GitHub Pagesで公開します。閲覧時のログインは不要で、ソースコードも公開です。事案記録は各利用者のブラウザー内に保存され、GitHubのリポジトリやサーバーへ送信されません。

`main` にpushすると、構文確認と自動テストに成功した版だけを公開します。Pull Requestでは検証だけを実行します。公開対象は `dist` から生成した `_site` の画面ファイルです。

```powershell
git add dist README.md
git commit -m "Update ACTION OS"
git push origin main
```

公開ごとにGitのコミットIDをオフラインキャッシュ名へ設定します。新版の取得後、開いているACTION OSのタブをすべて閉じて再度開くと切り替わります。処置中の画面を強制更新する処理はありません。

以前のChatGPT Sites版やローカル版とは保存領域が異なります。既存の事案記録を移す場合は、以前の画面でJSONを書き出し、新しい公開サイトで復元してください。

## 起動

Node.jsがある端末で、このフォルダーを開きます。追加パッケージのインストールは不要です。

```powershell
npm start
```

表示された `http://127.0.0.1:4173` をブラウザーで開きます。終了はターミナルで `Ctrl+C`。
`index.html` の直接ダブルクリックでは、モジュールとオフライン機能が動作しないため、HTTPサーバーを使用してください。

## 実装内容

- 事象選択、対応の再開、同じページ内の分岐・複数の詳細展開・引き継ぎ・記録終了。
- 成人：安全、反応、呼吸、胸骨圧迫、条件付きの人工呼吸30：2、AED、回復の再確認、救急隊への引き継ぎ。
- 119・応援／確認と処置／AEDの搬送を並行表示。人数や担当者の事前登録は不要。
- AED到着、電源、パッド装着、解析、機器からの指示、ショック、圧迫の再開、交代を別々に記録。
- AED解析・ショック中の現在の行動は「全員離れる」。復帰後の古い指示は再利用しない。
- 火災・地震・大雨／浸水の公的資料に基づく共通初動と具体的な分岐。施設固有の避難経路などは未確認。
- 複合事象の枝追加、担当・メモ、観察結果と時刻の訂正履歴、過去の実施内容の補記。
- 実対応と訓練の分離。訓練では電話リンクを生成しない。発信画面を開く操作だけで通報完了にしない。
- 自動保存、読み込み時の復元、JSON書き出し・復元、印刷。
- 保存失敗と別画面からの更新競合を表示。異なる同一IDの復元データは別コピーにする。
- 白・濃紺・青・赤のレスポンシブ表示。外部フォント、解析サービス、CDN依存なし。

## 保存とオフライン

記録は、そのURLを開いたブラウザーの `localStorage` の `action-os.v1` に保存されます。端末・ブラウザー・URLが異なると保存領域も別です。`localhost` と `127.0.0.1` も別領域です。

「この端末に保存済み」は保存処理の成功後だけ表示します。保存できないときは画面内で警告し、メモリ上の記録を書き出せます。書き出したJSONには担当者やメモも含みます。

「端末と施設の準備」で「オフライン準備済み」を確認してください。Service Workerが画面と必要なファイルを保持し、準備済みの同じブラウザーからオフラインで再利用できます。初回起動にはオンライン接続、またはローカルHTTPサーバーが必要です。HTTPSまたはlocalhostで利用してください。

ブラウザーのデータ削除や端末の故障で端末保存は失われるため、必要な記録は書き出して保管してください。クラウドへの自動送信はありません。外部の公式資料リンクを開く場合は通信が発生します。

## 記録の扱い

観察は未回答と「わからない」を区別します。一度の行動、継続する処置、繰り返す解析等は、それぞれ別のイベントとして時刻を保持します。

訂正は元のイベントを書き換えず、対象イベントID・変更値・訂正理由・記録時刻を追記します。表示は訂正を反映し、元の値も履歴に残します。出来事の表示順は記録順で、実際の時刻と記録時刻を分けて保持します。

過去の実施内容の「補記」は現在の機器指示に反映しません。現在の処置状態を更新する場合は、該当カードから現在の状態を記録してください。

「対応記録を終了」は記録を閉じる操作です。実際の引き継ぎ、処置を続けて記録だけ閉じる場合、その他をその場で確認します。処置の中止や危険解消には自動的に結び付けません。

## 採用資料と版

成人は消防庁「救急蘇生法の指針2020（市民用）」対応資料の別紙1を主資料とし、指定された東京消防庁・日本赤十字社資料を確認しました。通常時の手順に感染症流行期だけの特例を混ぜていません。

手順名、版、参照URL、資料確認日2026-10-20は `dist/model.js` と `dist/templates.js` にあり、事案の開始・枝追加時に複製して保存します。画面下の管理情報から確認できます。

新しい医療手順の版を採用する際は差分確認と新しいテンプレートIDが必要です。既存の事案のイベントやテンプレート管理情報を置き換えないでください。旧版を描画する処理を維持して更新してください。

## 開発

```powershell
npm test
npm run check
```

追加依存なしのHTML・CSS・JavaScriptです。

| ファイル | 役割 |
| --- | --- |
| `dist/app.js` | 画面、操作、復元時の最新指示確認 |
| `dist/model.js` | 記録、訂正、状態遷移、保存、復元検証 |
| `dist/templates.js` | 火災・地震・大雨の手順と出典 |
| `dist/style.css` | PC・スマホのレイアウト |
| `dist/sw.js` | オフライン用の画面キャッシュ |
| `tests/model.test.mjs` | 医療状態、履歴、保存失敗、復元のテスト |
| `server.mjs` | ローカル静的HTTPサーバー |

GitHub Pagesでは `scripts/prepare-pages.mjs` が公開用コピーのキャッシュ名を自動更新します。他の公開先へ `dist` を直接配信する場合はService Workerのキャッシュ名を更新し、旧キャッシュを利用中の事案へ不用意に新コードを割り込ませないでください。ローカル開発では同一オリジンのネットワークを優先し、取得できない場合にキャッシュを使います。

公開ワークフローは [GitHub Pagesの公式手順](https://docs.github.com/ja/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)に基づいています。
